## Known Issues / Technical Debt
- **MSE/PE outbound encryption is DONE (R4).** `PeerWireClient` attempts the MSE handshake before every connection (`.preferEncrypted` default) and falls back to plaintext for non-MSE peers, so the encryption-required peers that used to accept our TCP connection then go silent are now usable. Live-validated (2026-08-13): 12/13 connected peers negotiated RC4, 11 verified real pieces. **Remaining reach gap = no listening port:** we still never accept inbound, so NAT'd inbound-only peers (which drop our SYN — ~76% of a public swarm in the earlier diagnosis) stay unreachable, and swarms with no reachable seed at all can still time out. Adding a listener would break the download-only posture and is intentionally NOT planned. Avoid rapid repeated live magnet runs while testing — hammering shared trackers/peers appears to transiently throttle the source IP.
- Magnet metadata resolution (`MagnetMetadataResolver`) is concurrent + reachability-aware: `collectPeers` returns on `enoughPeersToStart = 300` or an 18s deadline (whichever first, then cancels stragglers) so a slow DHT no longer stalls the "Contacting…" stage; the fetch phase runs `maxConcurrentMetadataFetches = 24` workers over a `PeerCursor` actor (broad first pass over up to `maxMetadataPeers = 300`, then retries only peers that connected via `markReachable`), first SHA-1-verified metadata wins, bounded by `metadataPhaseDeadline = 90s`. `PeerWireClient.readUntilMetadataHandshake` stops at the peer's extension handshake (`receivedExtendedHandshake`) so a reachable leecher is dropped in ~1 RTT. `connectTimeout` for metadata probes = 8s.

Persistence stores the `info` dict per item to rebuild the metainfo offline; if a stored `info` dict ever fails to parse, that row is silently dropped on restore rather than shown broken.
- Download throughput can be capped via a shared `RateLimiter` token bucket. Limiting is applied *after* each chunk/piece is read (it throttles by pausing the read loop), so the cap governs the running average rather than instantaneous burst; a peer piece larger than one second's budget is admitted after a proportional wait.
- Manual app bundling is required because the current project is an SPM executable instead of a native Xcode app target.
- The Big Buck Bunny magnet link (documented in README) drives magnet-path testing (info-hash → metadata exchange → swarm). New test assets live in the repo root, not an external directory.

## Decisions & Rationale
- **Pure Swift/Apple-only:** Uses SwiftUI, Observation, Foundation, Network, CryptoKit, AppKit, and UniformTypeIdentifiers only.
- **Download-only:** No peer listener, tracker port is `0`, uploaded is always `0`, no block upload handling, and completion sends stopped announce. MSE/PE encryption (R4) changes only the outbound transport — no seeding is introduced.
- **MSE/PE is pure Swift:** CryptoKit has no custom-group Diffie-Hellman, so `MSECrypto.swift` implements DH over MSE's fixed 768-bit prime with a minimal `BigUInt` modexp plus RC4; SHA-1 (`HASH`) uses CryptoKit. `crypto_provide` advertises RC4 only, so any completed MSE handshake yields an encrypted stream; plaintext-only peers are handled by the fresh-socket fallback.
- **Default downloads location:** Uses the system `.downloadsDirectory` URL so localized user folders work correctly.
- **Transmission reference:** Transmission was consulted for protocol concepts only; no code was copied or translated.
